### Findings

[NOTE] kx3rig/controller.py:218-221; kx3rig/radio.py:253-260, 408-413, 505-509, and 558-582. Key-down can still be approved against SPLIT, XIT, or frequency state that is not the radio's current one. Re-checked in this run: still present. The in-scope part is unchanged: `can_transmit` reads SPLIT and XIT from the main-loop copy (controller.py:218), and the `ptt` gate compares only frequency and mode (radio.py:256-259). radio.py has no commits since the last scan. Its cited lines were re-read, and windows (2) and (3) were not re-probed. The new `retry` flag opens no window, because a retried FT8 key-down re-runs `check_tx` and the `ptt` gate. Confidence: high that each window exists; low that any occurs in normal operation.
  Attack vector: No adversary. (1) A SPLIT or XIT change that the link has read but the main loop has not yet applied passes, because `ptt` compares neither flag. (2) A rejected frequency SET. `_get("FA;")` returns the SET's `?;` as its answer (radio.py:412-413), `_tuning` then clears (radio.py:564-566), and both copies hold the requested frequency until the next IF reply. (3) Reconnect. `_handshake` publishes CONNECTED (radio.py:505) before it reads IF (radio.py:506-509). An active FT8 contact stops when the main loop sees the link down, but Tune, Talk, and a newly started contact are exposed for one IF round trip.
  Evidence: Demo emulator, General class, DATA mode, this run. SPLIT was set on the emulator, and the link saw it after 0.20 s while the main-loop copy still showed it off. `can_transmit` and `play_data` were allowed, and RTS rose. XIT behaved the same way. Windows (2) and (3) were reproduced in the 2026-10-10 scan; the rejected SET keyed on 14.230 MHz after the check approved 14.074 MHz in 5 of 5 runs.
  Remediation: In `ptt(True)`, refuse when the link's live `split` or `xit_on` is set. Keep `tuning_pending` true until an FA or IF reply read after the SET confirms the new frequency. Treat `?;` or a missing reply as unconfirmed, and match the GET's own reply rather than a `?;` left over from the SET. Read IF before publishing CONNECTED, in the same state update. Ideally, read IF just before asserting RTS.

[NOTE] kx3rig/ft8/engine.py:128-133; kx3rig/radio.py:253-260, 419-431, and 543-547. The FT8 submode check can pass on a stale submode. Re-checked in this run: still present. An unknown submode refuses (engine.py:129-130, tested at tests/test_station.py:349-355), but a stale known value passes. The link reads DT only every fifth poll cycle in a data mode (radio.py:543-547), not when an IF reply shows a change into DATA (radio.py:419-431), and the `ptt` gate does not compare the submode. Confidence: high on the code behavior (reproduced). Low on the on-air effect, because the sourced references do not describe the sideband and signal source of the other submodes.
  Attack vector: No adversary. An operator who changes the submode on the front panel and starts FT8 or Tune within about a second passes the check on the old value.
  Evidence: This run, emulator. After the emulator's submode was set to AFSK A, `check_tx` and `play_data` were allowed at once, and RTS rose. The link saw AFSK A 0.60 s later.
  Remediation: Read DT whenever an IF reply changes the mode into DATA. Include the submode in the `ptt` gate for data transmissions, for example as an `expect_submode` argument compared with the link's live value.

[NOTE] kx3rig/bandplan.py:187 and 213. `tx_check` and `privilege_segments` still default `license_class` to "General". Re-checked in this run: still present. Confidence: high that no current caller omits it. The only app caller of `tx_check`, `Station.can_transmit` (controller.py:221), passes `settings.license_class`, which defaults to Technician and is reset to Technician when unknown (config.py:35 and 67-68). `privilege_segments` has no app caller; only tests/test_bandplan.py:89 calls it, with "General".
  Attack vector: No adversary; the gap is latent. A future transmit path that called `tx_check(dial, mode)` would approve General segments for a Technician operator.
  Remediation: Make `license_class` a required parameter in both functions, or default it to "Technician".

[NOTE] install.sh:27-28, constraints.txt:1-8, pyproject.toml:2. Install-time code is still fetched unpinned (carried from the 2026-10-10 scan, not re-checked). numpy and pyserial resolve to the versions in constraints.txt. install.sh:27 upgrades pip with no version. The `setuptools>=64` build backend is installed into pip's isolated build environment, where `-c` does not apply. The pins carry no hashes. Confidence: high that pip and setuptools are unpinned; exploitation needs a compromised release.
  Attack vector: A compromised future release of pip or setuptools on PyPI runs with the user's privileges during `./install.sh`, building the venv of an app that keys a transmitter.
  Remediation: Pin pip (for example `pip install 'pip==26.2.1'`) or drop the upgrade. Add a tested `setuptools==` pin to constraints.txt and pass `--build-constraint constraints.txt`. Consider hashed pins with `--require-hashes`, and run `pip-audit` before releases.

[NOTE] HEAD tree, location withheld (outside this run's scope). One line still contains the 4-character prefix of the grid locator that the history scrub removed (carried from the 2026-10-10 scan, not re-checked). The scrub replaced that prefix in the tests, where it was paired with the scrubbed callsign. This line pairs it with a different callsign, so it does not identify the operator by itself. The file and line are not recorded here because this repository is public; they were given in the 2026-10-10 scan's session output. The line is not in this run's files: connect_page.py and style.css contain no locator-shaped token, the screenshot shows none, and the 2026-10-10 scan found no match in the other four. Confidence: high that the value matches. Low that it matters, because a 4-character locator spans 1 degree of latitude by 2 degrees of longitude.
  Attack vector: A reader of the public repository learns the operator's region only if something ties this locator to the operator. Nothing in the tree does; a precise citation in a committed file would.
  Remediation: Replace the locator in that line with one unrelated to the station, as the scrub did in the tests, or record it under Accepted Risks. Include the 4-character prefix in future identity searches. Keep the location out of SECURITY.md, CODEREVIEW.md, and commit messages.
